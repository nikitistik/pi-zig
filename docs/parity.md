# Pi-Zig Parity Ledger

Status values:

- `not_started`: inventory only.
- `foundation`: partial local representation exists, not behavior-complete.
- `in_progress`: behavior is being ported and tested.
- `verified`: parity is backed by tests and runtime evidence.

Current checkpoint evidence:

- Agent/RPC extension path: `--mode rpc --session <file> --extension <hook.mjs>` now binds explicit tool hooks, and `--extension <tool.mjs>` / `<tool.ts>` expose registered tools to RPC provider prompts.
- Runtime extension discovery: provider-backed JSON/text/RPC now execute enabled discovered `.js`/`.mjs`/`.ts` extension paths from project/user/package discovery; full upstream `jiti` aliasing, virtual modules, dependency roots, and long-lived extension state remain open.
- Extension command inventory: `commands` and RPC `get_commands` now load extension `registerCommand` metadata, emit extension slash commands before prompts/skills, and assign upstream-shaped duplicate invocation names such as `deploy:1` / `deploy:2`.
- Extension tool gating / headless UI: JSON and RPC provider loops now verify extension-registered tools still execute under `--no-builtin-tools`, can be selected by `--tools ext_echo` without leaking built-ins, and can block a provider-requested `bash` call through headless `ctx.ui.confirm() === false` before shell execution.
- RPC retry/events/abort: provider-backed RPC prompts now emit upstream-shaped `agent_end.willRetry`, `auto_retry_start`, and `auto_retry_end` events for transient success and exhausted retry paths, run prompts on an active worker so `abort_retry` can be accepted during retry delay, keep `abort_retry` as a cancellation-only command instead of disabling future retries, cancel retry sleep with `auto_retry_end.finalError = "Retry cancelled"`, accept general `abort` while a provider-backed prompt is active, persist aborted provider prompts as assistant messages with `stopReason: "aborted"` / `errorMessage: "Request was aborted"`, persist final provider/runtime failures as assistant messages with `stopReason: "error"`, emit `message_start` / `message_end` / `turn_end` / `agent_end` for failed assistant turns, and skip failed assistant messages when rebuilding provider history; provider-backed prompts still avoid retrying non-transient provider 4xx client/auth failures, and classify upstream-like retryable provider body/error text while keeping context-overflow/request-too-large bodies non-retryable; cooperative AI-client cancellation checkpoints are threaded into provider calls/stream readers, but hard socket-level cancellation while blocked inside Zig `std.http` remains open.
- JSON retry/event recovery: top-level JSON no-tools text-stream and tool-capable provider paths now load retry settings, emit failed-attempt assistant lifecycle with `agent_end.willRetry`, `auto_retry_start`, successful `auto_retry_end`, and final `agent_end.willRetry=false`, and recover from transient provider failures in smokes; exhaustive top-level JSON retry and abort event parity remain open.
- Image-capable and non-vision tool results: built-in `read` now returns png/jpg/gif/webp files as text plus image content parts, appends the upstream non-vision note when the active resolved model lacks image input support, provider serialization downgrades unsupported direct-user and tool-result image parts to the upstream placeholders, and OpenAI-compatible provider continuation uses the upstream-shaped role=`tool` text result plus a synthetic user image message only for image-capable models.
- Verification: `scripts/verify-basic.mjs` includes fake-provider explicit and discovered extension smokes for rewritten `bash` tool calls/results, JS and TypeScript registered extension tools, same-name extension tool overrides for built-in `bash` definitions/execution in JSON and RPC, extension registered-command inventory in `commands` and RPC `get_commands`, `--no-extensions` explicit-only behavior, extension registered-tool execution under `--no-builtin-tools` and `--tools ext_echo`, headless permission-gate blocking for JSON/RPC provider loops, top-level JSON transient retry recovery for no-tools and tool-capable provider paths, retry success/exhaustion/retryable-provider-body/non-retryable-client-error/context-overflow non-retry classification, cancellation-only `abort_retry` state behavior, event-driven abort of active retry sleep, general `abort` delivery while a fake provider request is in flight plus aborted assistant lifecycle events and persisted `get_messages`/JSONL assertions, retry-exhausted and non-retry client-error assistant `stopReason: "error"` assertions, OpenAI-compatible read-image tool-result replay, non-vision direct image and read-tool image downgrade smokes, and durable RPC `get_messages` assertions; Zig unit coverage checks extension-vs-extension duplicate tool names use upstream first-extension-wins precedence, registered command duplicate names use upstream invocation suffixes, retryable provider error text and context-overflow classifier behavior, image serialization/downgrade behavior for OpenAI-compatible payloads, Google Vertex OAuth bearer routing, ambient Vertex access-token auth status, and tool-result image serialization for OpenAI-compatible, Anthropic, Google/Vertex, Mistral, and Bedrock payloads.
